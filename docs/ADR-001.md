# ADR 001: bounded durable graph and patch-only OpenCode workers

Date: 2026-10-18. Status: accepted for initial implementation.

## Evidence before architecture

The inspected host is Windows 11 Pro build 26200, Python 3.10.9/SQLite 3.40.1,
Node 24.20.0, Git 2.39.2, gh 2.102.0, OpenCode 2.0.32. The workspace parent is
not a Git repository. No Docker executable was discovered. gh is authenticated;
credentials remain in its keyring. The local HyperQwen source is at commit
95ee3b6 (recent history includes boolean validation and vLLM compatibility fixes).
Model A's actual `/v1/models` response advertises `qwen3.8-27b`, max_model_len
150000. Model B discovery initially timed out; availability is not assumed.

Upstream source snapshots are retained in `evidence/research`, with commit-pinned
URLs in `source-manifest.json`. Specifically inspected:

- [LangGraph SQLite saver](https://github.com/langchain-ai/langgraph/blob/0870f5ef/libs/checkpoint-sqlite/langgraph/checkpoint/sqlite/__init__.py): WAL, checkpoint and pending-write tables. [Durable execution](https://docs.langchain.com/oss/python/langgraph/durable-execution) requires idempotent effects; replay is not a distributed transaction.
- [gh merge implementation](https://github.com/cli/cli/blob/fa92838b/pkg/cmd/pr/merge/merge.go): mergeability, review/check policy, merge queues and head matching are separate concerns.
- [OpenCode V2 config source at installed tag](https://github.com/anomalyco/opencode/tree/843a6c514e606b436a7fe713422ace0a93ad3d61/packages/schema/src/config): V2 uses `providers`, `api.id` and structured options, not V1 `provider` aliases. Exact config and CLI integration must pass a real invocation before adoption.
- SWE-agent bounded action/retry loop and environment, OpenHands event/conversation state and confirmation policies: see `research-frameworks.md` and retained source. Adopt bounded tasks and external execution records, not a shared growing conversation.

## Decision

Use a small explicit Python execution graph backed by SQLite WAL, JSON state,
transactional node/event checkpoints and an external-effect ledger. Each node has
named contracts, conditional edges, bounded attempts, retained artifacts and a
failure destination. OS-backed per-repository locks prevent conflicting local
controllers and disappear when a controller dies. Side effects reconcile by stable
branch names and issue/PR markers on resume. Unknown remote outcomes fail closed.

LangGraph is a sound future host for these same node functions; it does not remove
the need for the effect ledger, Git isolation or GitHub policy verification. For
this single-host, sequential-per-repository deployment, a standard-library runtime
reduces installation and Windows failure modes. This deliberately accepts the
maintenance cost of a small graph runner and excludes distributed scheduling.

Codex supervises configuration, evidence, routing and approvals. Separate OpenCode
sessions receive bounded structured source bundles and return JSON proposals.
Workers cannot execute repository commands or directly publish GitHub changes.
The controller validates paths/content, applies edits only to isolated Git worktrees,
runs frozen regression tests and reviews the actual diff in an independent session.
Model output is never proof that tests passed or merge is eligible.

Test execution defaults to disabled until the operator explicitly trusts local code.
Environment filtering and worktrees are process hygiene, **not an OS sandbox**.
Hostile repositories require an external sandbox/VM and a separate credential-free
execution account before execution is enabled. GitHub operations run only in the
controller. Protected paths, policy files and existing tests cannot be edited by
workers. No target integration file or CI rewrite is required.

Human merge approval is the default and binds to a commit SHA. Optional automatic
merge needs explicit trusted-low-risk policy, independent passing verification,
fresh CI/review policy evidence, and exact PR head matching. No admin bypass.

## Consequences and rejected choices

- Worktrees isolate changes, not malicious processes; do not market them as sandboxes.
- Reject shell strings supplied by models, unrestricted agent execution, shared sessions,
  invented findings, LLM-only merge decisions, automatic CI/security rewrites.
- SQLite is single-host only. PostgreSQL leases/outbox, service authentication, isolated
  runners and an authenticated approval service are required for multi-host deployment.
- GitHub creation is not exactly-once: persist intent, reconcile markers after crashes,
  and block on ambiguous duplicates rather than blindly retry.
- Model B routing remains provisional until actual task measurements support it.
